# Exploratory playtest method

Use this self-review between playable checkpoints. The independent comparison protocol has its own conditions.

1. Pin the build and start a fresh browser profile. Record viewport, input, renderer, and any critical prior knowledge. Use ordinary controls, visible cues, and rendered frames. Leave camera coordinates, scripted routes, and implementation inspection for diagnosis.
2. At each decision point, write the cue, the action it suggested, the expected response, and what actually happened. Check arrival, one close interaction, and one deviation from the obvious route. Try looking away, approaching from another side, and returning to the view that first attracted attention. Capture a frame that explains each consequential finding.
3. Ask whether the cue belongs to the world, whether the action changed what the explorer noticed, and what question remains. Preserve effective compositions and mysteries. Prioritize issues that interrupt attention or make cause and effect hard to infer.
4. Make one coherent change with observable criteria. Replay the decisive moments in a fresh profile. Use the browser smoke suite separately for route coverage and invariants. Record which improvements were directly observed and which still require first-time humans. Software rendering, tool latency, and prior knowledge make elapsed time and navigation success unsuitable as human performance evidence.

For the next checkpoint, repeat the shore decision and try a second route without opening the journal. Capture the view just before and just after the turn. If the destination stays apparent but the local route needs repeated camera corrections, test stronger terrain contrast before adding interface guidance.
